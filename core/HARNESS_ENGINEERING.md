# Harness Engineering 規則

> **受眾：AI agent**
> 本文件列出可直接作為行為指引的執行規則。每條規則以「必須」或「不得」開頭，無需詮釋。

---

## 1. 範圍控制

- 只實作任務要求的功能，不得添加額外功能、重構或清理
- 修 bug 不得順帶重構周邊程式碼
- 不得為假設中的未來需求設計抽象層

## 2. 文件操作

- 優先編輯現有檔案，只有在嚴格必要時才建立新檔案
- 使用專用工具（Read、Edit、Write、Grep、Glob），不得用 shell 命令替代文件操作
- 讀取大型檔案時，使用 offset/limit 只讀取相關段落

## 3. 程式碼品質

- 不得添加無法在實際中發生的情境的錯誤處理
- 不得在未修改的程式碼中添加 docstring、注解或型別標記
- 不得添加向後相容的 shim 或 feature flag（除非明確要求）
- 預設不寫注解；只在「為什麼」非顯而易見時才加注解

## 4. Git 安全操作

- `force push` 到 `main`/`master`：必須停止並警告，不得提供指令
- `git rebase main`：必須確認影響範圍後才繼續
- 高風險操作（`reset --hard`、`push --force`）：必須先取得使用者明確確認
- 只有在使用者明確要求時才建立 commit

## 5. 技能呼叫行為

- 技能被呼叫但缺少必要輸入時：停止並列出缺漏的輸入項目，不得自行填充假設
- 缺少技能名稱或專案名稱時：停止並詢問，不得使用預設值
- 同一 session 內再次呼叫同一技能：詢問是否新建或修改現有輸出，不得直接覆蓋

## 6. 語言適應

- 以使用者的語言回應，不論 SKILL.md 使用何種語言撰寫
- 保持技能邏輯不變，只調整回應語言

## 7. Token 效率

- 回應以答案或行動開頭，跳過前置說明
- 並行執行獨立的工具呼叫，減少往返次數
- 不在任務完成後加入摘要（「以下是我做的事…」）

## 8. Adapter 邊界

- Adapter 只做格式翻譯，不修改技能邏輯
- 不得在 adapter 中新增 `skills/` 目錄中沒有對應技能的行為
- 所有 11 個技能必須出現在所有 adapter 中
