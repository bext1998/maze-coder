# idea-to-spec

## 目標

透過必要問答產出可供後續補強的 `spec.md`。

## 前置條件

- 至少取得一句需求描述；不足時列出缺漏並停止，不得猜測。
- 若已有規格，先確認要新建或修改。

## 執行流程

1. 確認專案名稱、核心問題、使用者、3–5 項核心功能、非目標與技術限制。
2. 依 `templates/spec.template.md` 填寫專案概述、核心問題、目標、非目標、功能清單、技術考量與成功指標。
3. 顯示草稿並請使用者確認；確認前不得寫入檔案。

## 輸出契約

- 寫入使用者指定路徑；未指定時使用 `spec.md`。
- 必須符合模板且所有必要 section 完整，不留空白佔位符。

## 邊界

- 不補強或驗證規格、不初始化專案、不撰寫程式碼、不代替使用者決定技術方案。
