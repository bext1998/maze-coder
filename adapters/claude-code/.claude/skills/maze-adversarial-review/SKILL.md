# adversarial-review

## 目標

嘗試證偽即將採用的方向，避免因表面合理、沉沒成本或既有 framing 過早相信方案。

## 前置條件

- 取得待審方案、決策目標、已知證據與限制；缺少足以辨識核心主張的內容時停止並要求補充。
- 優先由未參與方案形成、具有乾淨上下文的獨立 agent 執行；平台不支援時可由同一 agent 降級執行，但報告必須揭露 reviewer 不獨立及 framing bias 風險。

## 執行流程

1. 明列核心主張、隱藏假設、成功所需條件與可推翻條件，不把偏好或直覺當成事實。
2. 針對高代價、難回復或證據最弱的主張，設計反例、失敗情境與最小反證查核。
3. 公平提出至少一個有力替代解釋或方案；若不存在合理替代，記錄搜尋範圍，不湊數。
4. 依實際證據判定哪些主張仍成立、已被推翻或無法判定；時間壓力與沉沒成本不得降低證據門檻。
5. 產出簡短決策挑戰報告，結論只能是 `go`、`revise`、`stop` 或 `insufficient evidence`。

## 輸出契約

- 報告包含：審查目標、reviewer 獨立性、核心主張與可推翻條件、已執行的攻擊、反證或限制、殘餘不確定性、結論與理由。
- `go` 只代表在已列攻擊範圍內未找到足以阻止方案的證據，不代表方案已被證明正確。

## 邊界

- 唯讀；不修改原方案、不開始實作、不替使用者承擔產品決策。
- 不取代 `maze-grill` 的需求釐清，也不取代 `maze-spec-review` 的完整性審查。
- 不因找不到反例就虛構問題，也不以一般風險清單冒充證偽。
