# 規格審查清單

## 六面向

- 需求完整性：角色、目標、範圍、輸入、輸出與成功條件。
- 邏輯一致性：術語、流程、狀態、依賴與規則互不矛盾。
- 邊界與失敗情境：空值、權限、重試、並行、資料遺失與回復。
- 可實作性：現有架構、型別、資料流、平台與依賴是否支持。
- 可驗收性：行為、錯誤、相容性與測試是否可觀察、可重現。
- 設計系統相容性：既有 UI／UX、元件、內容與無障礙約束。

## Finding 與結論

- Blocker：無法安全實作或有關鍵資料／安全風險。
- Major：可開始但極可能返工。
- Minor：不影響核心實作的缺漏。
- Suggestion：非必要品質改善。
- 結論依序為：Blocker→阻擋實作；Major→需修訂；僅 Minor／Suggestion→可開始但有備註；無 finding→可開始。
- 證據明確區分已查證事實、推論與 `unverified`。
