# 對抗式韌性驗證

高風險技能（邊界依賴「已證明」「根因」「風險」等判斷性措辭，錯誤解讀代價高——會導致隱藏 bug、資料損毀或驗證被跳過）在定稿前，用以下方法驗證措辭在壓力情境下是否還能約束行為。低風險技能（文件同步、資訊彙整類）不需要。

## 怎麼做

1. 針對技能最容易被繞過的 1-3 個判斷點，各設計一個帶壓力框架的具體情境（時間壓力、沉沒成本、看似合理的豁免理由）。
2. 用一個獨立 subagent，給它技能全文＋情境，要求「具體說出接下來會執行的下一步」，不要只複述規則。
3. 判定通過：subagent 的具體行動仍符合技能核心限制（沒有跳過驗證、沒有用症狀修補掩蓋根因、沒有濫用豁免條款）。
4. 多數情境失守才需要調整措辭；單一情境失守先檢查是否只是措辭模糊，不必急著擴寫成長文件。

## 邊界

- 不為了防禦重寫成冗長條款；優先確認「已證明」「根因」等關鍵字本身是否清楚，而非增加篇幅。
- 通過的驗證不需要另建檔案存證；在 PR 描述或 commit message 說明測過的情境與結果即可。
