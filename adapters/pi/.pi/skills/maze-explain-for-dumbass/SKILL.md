# explain-for-dumbass

## 目標

agent 常把正確內容包上術語、被動語態、流程敘述，讓人要花力氣反推結論。把已講完的
技術性內容重講成外行也懂的版本——不重做任務，只重講結論。語言無關，不綁定
ASD-STE100 等綁定英語的受控字彙表。

## 前置條件

- 有一段剛講完、對方表示聽不懂或要求「講人話」的技術性回覆。
- 不用於 spec.md、ADR 等需要精確措辭的正式文件。

## 執行流程

1. 找出最近一則回覆的核心結論：做了什麼、對什麼對象生效，不是過程描述。
2. 抽出不可簡化資訊——檔案路徑、指令、版本號、錯誤碼、API／函式名、環境變數——原樣
   保留，不意譯或省略。簡化＝重排＋加註，不是刪除。
3. 不重跑任務、不產生新結論，只重寫措辭；新版本須與原回覆結論一致。
4. 依輸出契約重寫，取代原回覆呈現方式。

## 輸出契約

- 第一句話是具體結論，不是過程敘述，接著 2-4 句白話說明。
- 需要行動時給可複製指令的「你現在要做的」區塊；不需要就省略。
- 技術細節原文用 `<details>` 摺疊保留。
- 可機械檢查：原文檔名／指令／錯誤碼須 100% 出現在簡化版；摘要層字數 ≤ 原文 40%。

## 邊界

- 不重做任務、不改變技術結論，只是重新表達。
- 不用於正式文件，不做客套話，不為口語化犧牲正確性。
- v1 不做：常駐觸發、懂度分級、術語表、理解力驗證。
