# threat-modeling

## 目標

在設計仍可調整時，找出跨越信任邊界的高價值威脅與濫用途徑，轉成可驗收的安全條件。

## 前置條件

- 取得系統目的、資料流、外部整合、身分／權限模型及部署邊界；缺少內容標為未驗證，不自行假設安全。
- 先界定本輪分析範圍與保護目標；不要求完整程式碼或已完成實作。

## 執行流程

1. 盤點資產、敏感資料、信任邊界、入口、外部依賴與具權限的操作。
2. 描述相關攻擊者及其能力、限制與目標，不預設所有使用者均可信或所有威脅均為外部來源。
3. 沿資料流與狀態轉換建立具體濫用途徑，說明如何跨越信任邊界、影響哪些資產及現有控制。
4. 依影響、可行性與現有控制排序威脅；不以未量測的精確分數製造確定性。
5. 為優先威脅提出最小緩解措施、需要驗證的假設及應納入規格與驗收的安全條件。

## 輸出契約

- 輸出範圍、資產與信任邊界、攻擊者、優先威脅與濫用途徑、緩解措施、未驗證假設、安全條件及殘餘風險。
- 證據不足時明列需要補充的資料，不宣稱系統安全。

## 邊界

- 不執行程式碼漏洞掃描、滲透測試或完整 security audit。
- 不主動利用真實系統、不接觸未授權資料、不提供超出防禦驗證所需的攻擊操作。
- 不取代通用對抗性方案審查；本技能只處理安全資產、攻擊者、信任邊界與濫用風險。
