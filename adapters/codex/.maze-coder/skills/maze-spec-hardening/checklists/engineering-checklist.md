# 工程層補強檢查清單

在補強 spec.md 的工程面向時，確認以下項目已涵蓋：

## 介面契約（Contract）

- [ ] 每個核心組件的輸入要求是否明確？
- [ ] 每個核心組件的輸出格式是否定義？
- [ ] 失敗行為（輸入不足、錯誤輸入）是否有明確的處理方式？
- [ ] 是否避免了「自動填充假設」的失敗模式？

## 系統不變式（Invariants）

- [ ] 目錄 / 檔案結構約束是否明確？
- [ ] 命名規則（大小寫、格式）是否一致且明確？
- [ ] 狀態一致性要求是否定義（例如：A 存在時 B 必須存在）？
- [ ] 每個不變式是否有「違反時的症狀」描述？

## FROZEN 決策

- [ ] 哪些決策在當前版本期間不得修改？
- [ ] FROZEN 決策是否列出了「變更需同步更新的位置」？
- [ ] FROZEN 標記是否清楚標示在 spec 中？

## 技術限制

- [ ] 平台 / OS 限制是否明確？
- [ ] 外部依賴是否明確列出並說明版本要求？
- [ ] 效能 / 安全約束是否記錄？

## 可攜性

- [ ] 是否定義了「可攜式」的操作定義？
- [ ] 安裝 / 設定步驟是否符合可攜性要求？
