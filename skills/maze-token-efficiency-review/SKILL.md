# token-efficiency-review

## 目標

以可查證證據找出可節省 token 的改善，不降低正確性、覆蓋率或能力。

## 前置條件

- 取得可用 trace、工具紀錄、已載入內容與模型／技能選擇；缺漏資料須標記證據不足。

## 執行流程

1. 對照目標與實際 trace，辨識重複讀取、過度探索、錯誤技能／模型、可腳本化工作及無效輸出。
2. 對每項記錄證據、估計節省量、風險與能力影響，依「節省量高、風險低、能力無損」排序。
3. 僅實施可驗證且維持正確性、覆蓋率與能力的變更；其餘只提出建議並說明所需證據。
4. 驗證已採變更的結果，確認沒有跳過必要讀取、檢查或功能。

## 輸出契約

- 輸出發現（含證據與排序）、已採變更、驗證結果及剩餘風險；無可採變更時明確回報。

## 邊界

- 不以省 token 為由減少必要證據、驗證、覆蓋率或使用者要求的輸出；不憑猜測實施變更。
